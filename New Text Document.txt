# 3. REMOVE THE Future.delayed HACK

The audit identified that `PostCubit` uses a `Future.delayed` to return from `PostCreated` to `PostLoaded`.

This should be removed if it is only being used as a timing workaround.

We already have a real-time Firestore stream:

```text
snapshots()
```

Therefore the flow should rely on the stream to update the feed.

Expected behavior:

```text
PostCreating
      ↓
Create post in Firestore
      ↓
Firestore snapshots()
      ↓
PostCubit receives updated posts
      ↓
PostLoaded(updated posts)
```

Do NOT use arbitrary delays such as:

```dart
Future.delayed(...)
```

to synchronize UI state with Firestore.

Use the existing real-time stream correctly.

## Important

Be careful not to create duplicate subscriptions.

Make sure:

* The posts stream is subscribed once.
* `PostCubit.close()` cancels the subscription.
* Creating a post does not create another posts stream.
* No memory leaks.
* Existing real-time behavior remains intact.

If `PostCreated` is no longer needed after this change, remove it only if it is genuinely unused.

Do not remove states just for the sake of removing them.
